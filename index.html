05

Repo Structure

Everything in one repository. Four top-level directories — Terraform, Rego, Agents, Drata — each with its own README, clear ownership, and CI gate. Control library, policy engine, and AI agents side-by-side.

🏗️
terraform/
Infrastructure Controls

All PCI CDE infrastructure defined as code. Four provider modules. Scanned by Drata CaC Action, tfsec, and Checkov on every PR.

  • modules/aws-pci/ — KMS, CloudTrail, GuardDuty, Config, SGs
  • modules/gcp-pci/ — CMEK, Audit Logs, VPC firewall, Org Policies
  • modules/cloudflare-pci/ — TLS 1.2+, WAF, OWASP, HSTS
  • modules/drata-setup/ — Cross-account IAM + GCP SA for Drata
  • environments/production/ — root module, tfvars.example
📋
rego/
OPA/Rego Policy Engine

Policy-as-code rules organised by framework. Evaluated against Terraform plan JSON in CI. Also deployed as Kubernetes admission controller.

  • soc2/cc6_access_control.rego — MFA, IAM, SG policies
  • soc2/cc7_system_operations.rego — CloudTrail, encryption, GuardDuty
  • iso27001/annex_a_technology.rego — A.8 controls
  • pci_dss/requirements.rego — Req 1,2,3,4,6,7,8,10,11
  • shared/helpers.rego — common utilities, tag checks, CIDR helpers
🤖
agents/
AI Agents + Prompts

Configurations, prompts, and workflows for all AI agents. Every agent has a defined HITL gate — AI drafts, human approves before any action.

  • drata-mcp/ — Claude MCP config, slash commands, query examples
  • evidence-collector/ — Control narrative prompt for auditor packages
  • questionnaire-assistant/ — Questionnaire response prompt + HITL rules
  • tprm-agent/ — Vendor risk scoring prompt + tier definitions
🗺️
drata/
Drata Control Mappings

JSON files mapping each Drata control ID to the Terraform resources, Rego policies, and Config rules that provide automated evidence. The bridge between GRC and engineering.

  • control-mappings/soc2-terraform-map.json
  • control-mappings/iso27001-terraform-map.json
  • control-mappings/pci-terraform-map.json
  • hitl-gates.md — all 8 gate types, owners, SLAs
⚙️
.github/workflows/
CI/CD Pipelines

GitHub Actions workflows orchestrating the full compliance gate. PRs run all scanners. Merges trigger Terraform apply. Daily cron monitors live compliance state.

  • compliance-pr-gate.yml — Drata CaC + tfsec + Checkov + Rego + Plan
  • terraform-apply.yml — OIDC auth, apply on main merge
  • compliance-monitor.yml — daily AWS Config + GuardDuty + Sec Hub check
🌐
docs/
GitHub Pages Site

This website. Four pages covering the full GRC programme — compliance tracker, deployment guide, GRC Engineering roadmap, and PCI dashboard. Auto-deployed on merge to main.

  • compliance-as-code.html — this page
  • index.html — PCI compliance dashboard
  • deployment-guide.html — step-by-step setup
  • grc-roadmap.html — GRC Engineering Club alignment
06

Human-in-the-Loop Gates

AI accelerates; humans govern. Every consequential output — evidence submissions, risk scores, questionnaire responses — has a defined reviewer, SLA, and escalation path. Non-negotiable.

🚨 Critical
Audit Evidence Submission

Drata auto-collects, AI writes narratives. Before any package goes to 360 Advanced or Wipfli — GRC Lead reviews and approves every control narrative.

Approver: GRC Lead / CISO · SLA: 48h
🚨 Critical
Risk Register Updates

AI flags new risks from GuardDuty and Drata findings. No risk is closed, accepted, or treated without explicit human sign-off in Drata by the risk owner.

Approver: Risk Owner + Sec Manager · SLA: 5 business days
🔍 Review
Questionnaire Responses

Drata AI + Claude pre-fill incoming security questionnaires from SafeBase Trust Center data. Security Analyst reviews every answer before it leaves Branch.

Approver: Security Analyst · SLA: 2 business days
🔍 Review
Vendor Risk Scoring

Drata Agentic TPRM assesses vendors autonomously. GRC Analyst reviews the agent's reasoning and evidence before accepting any score into the risk register.

Approver: GRC Analyst · SLA: 3 business days
🔍 Review
Control Exceptions

When a Rego or Config rule flags a violation that can't be immediately fixed, an exception must be reviewed, justified, and time-bound. Never silently suppressed.

Approver: Sec Manager + Control Owner · SLA: 48h
🔍 Review
Policy Attestation

Drata sends automated attestation requests. GRC Lead reviews completion rates before each audit period — incomplete attestations require escalation.

Approver: GRC Lead · SLA: Monthly review
✓ Auto Block
CI Compliance Gate

Drata CaC + tfsec + Checkov + Rego automatically block non-compliant PRs. No human needed to block — human required to override via documented exception.

Override by: Sec Engineer + GRC Lead
✓ Auto Alert
Control Failure Alerts

GuardDuty CRITICAL and Config NON_COMPLIANT auto-alert via SNS + Slack. Human on-call response required within SLA. CRITICAL = 2h, HIGH = 24h.

On-call: Security Engineer · CRITICAL SLA: 2h
